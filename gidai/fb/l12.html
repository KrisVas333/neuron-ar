Game On — it's raining, so we play inside: Simon Says, then a game we build and code ourselves. "Today I learn to make a RULE."

▶ OPEN THE DECK — L12 Game On (HTML, press N for notes)

THE TAKEAWAY — WHAT THIS LESSON IS FOR

The kids learn that a rule is IF … THEN, then build a live game and code its rules: IF a colour reaches the sensor, THEN a sound plays.

  • Technical: the kids put the rule into the code themselves (bigger kids drag one block, younglings tap one animal). Don't do it for them.
  • Teamwork: four kids, one game. Each colour has a turn at the tablet, the others build the world around the track.
  • Language: every rule is said out loud as "IF ___ THEN ___". That sentence is the lesson.

Prepare from this guide, not only the slides. The slides don't carry these goals.

AT A GLANCE — THE 1-MINUTE VERSION

🎯 WHAT THIS LESSON WANTS FROM YOU:

teach one word — IF … THEN (a rule; the grown-up word is CONDITIONAL) ·

one technique — design a game: pick a winner and the sounds, code one IF for each colour, play it, pass the tablet ·

one belief — "Every game runs on rules, and I can write them." If the kids leave with those three, you won.

"Today I learn to make a RULE."  (the Promise — Slide 7, checked on Slide 22)

WHAT THE KID WALKS OUT WITH: a live game their crew built and coded: a figure rolls to the sensor and the rule decides the sound.

✅ SUCCESS: at slide 22 the kid says the two words of a rule and their own IF … THEN  ·  ❌ FAIL: the mentor coded the rules and the kids only pushed play

How this code works — explained for mentors

Block by block (top to bottom)

  1. when left motor turned ↻ — the start: a kid spins the wheel.
  2. run ↺ for 3 rotations — the cart rolls the figure to the sensor.
  3. if ⟨detecting red⟩ then — the rule. It checks once, when the cart has stopped.
  4.   play sound Win until done — only if the rule is true.

A false IF does nothing: that is why blue gives silence.

SLIDE 13Try it! One block goes in (bigger kids only)90: 9 · 60: 0 min

  • ❓ "What does your rule say?" → "IF red, THEN Win."
How this code works — explained for mentors

What the kids change

One thing only: the loose detecting red block goes into the empty hexagon of the IF. Everything else is ready.

Most likely mistakes

  • The block sits next to the IF, not inside. It must click into the hexagon.
  • The figure overshoots the sensor. The IF checks only when the cart stops: fewer rotations.
  • Nothing happens on the spin. Program not playing, or the wrong motor is being turned.

If it doesn't work, check…

Red figure on the cart? Play on? Right motor? Right way? Fewer rotations.

How this code works — explained for mentors

Icon blocks: there is no IF tile

Each row reads like a rule: [sees red] → [cat sound] = IF red THEN meow. One row per figure colour.

The last row: [spin tile] → [motor ↻ 1] — a kid spins the wheel, the cart rolls.

If it doesn't work, check…

Tablet paired · play pressed? Spin-tile row misbehaves? Press ▶ instead: the cart rolls past the sensor.

How this code works — explained for mentors

The finished program (the picture: blue wins)

  1. when left motor turned ↻ → run ↺ 3 rotations — same start as slide 13.
  2. if ⟨detecting blue⟩ then play sound Win — the winner's rule.
  3. if ⟨detecting red⟩ then play sound Meow — red's rule, its own sound.
  4. …one more IF for green, one for yellow, each with its own sound.

Most likely mistakes

  • Two IFs play Win. The copied IF kept Win: change the sound.
  • The new IF sits outside the stack. It must snap under the one before.
  • Colour not changed in the copy. Two rules for red, none for green.
  • A building blocks the sensor. Keep its view clear.
